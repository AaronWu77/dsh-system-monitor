## 概述

打开现有右侧栏，选择**新标签页 → 本机资源**。四个资源按钮切换 CPU、内存、GPU 与磁盘，初始选中 GPU。面板沿用 DSH 主题，不新增常驻聊天顶部按钮或左下角卡片。侧栏布局属于会话，指标始终属于运行 DSH Host 的本机；切换 SSH 工作区或从其他设备访问浏览器都不会改变采集目标。

## 使用

顶端资源行包含四个真实按钮：**CPU**、**内存**、**GPU** 与**磁盘**。当前按钮保持按下状态，并显示一类资源的详情与一条近期历史趋势。初始选中 **GPU**；资源按钮也支持键盘操作。

CPU 显示逻辑处理器矩阵；内存显示已用／可用组成与容量；GPU 显示弧形利用率仪表、专用显存条、共享显存读数与引擎数值；磁盘将物理磁盘活动／读写数值与分区容量条分开，分区容量不代表物理磁盘利用率。

打开后会进行短暂的速率计数器预热。**暂停**冻结当前视图并释放实时订阅，暂停时仍可切换资源；**恢复**重新实时采集，**重新连接**立即重连。未知数据明确显示为不可用，不冒充 0。某类指标读取失败时保留最近有效值，并标记其已经过期。

颜色继承 DSH 语义 token，跟随全局 GUI 外观；插件没有独立的浅色／深色开关。资源按钮与详情随侧栏宽度调整，包括 390 px 浏览器视口。内容超出侧栏可用高度时在面板内滚动；聚焦面板后也可使用键盘滚动，包括 Home 与 End。

只有可见的实时面板订阅数据。切换标签页、暂停、关闭面板或将浏览器隐藏，会释放或挂起 HTTP 流。最后一个查看者断开后，Host 在配置的宽限期结束时停止共享采集器。多个面板或浏览器窗口共用一套采集。完全停采后重新打开会建立新的短历史，不承诺记录后台历史。

## 配置

[组合补丁](cordis.patch.yml) 插入一个独立 Host 插件，浏览器入口通过包清单发现。构建后还需安装到指定 DSH profile；构建本身不会安装。Host 验证配置，并通过已鉴权接口向浏览器提供生效的时间参数。

| 字段 | 默认值 | 含义 |
|---|---:|---|
| intervalMs | 1000 | 采样周期，整数 500–10000 毫秒。 |
| capacityIntervalMs | 60000 | 固定分区容量与显卡清单刷新周期，10000–3600000 毫秒。 |
| historySeconds | 60 | 内存中的趋势窗口，30–300 秒。 |
| idleGraceMs | 1500 | 最后一个查看者断开后的宽限期，0–10000 毫秒。 |
| workerStopTimeoutMs | 5000 | 优雅关闭 Worker 的期限，超时强制终止，1000–30000 毫秒。 |
| reconnectMs | 2000 | 流失败后的重试间隔，1000–30000 毫秒。 |
| streamTimeoutMs | 30000 | 两个有效流帧之间的最长期限，3000–60000 毫秒，应明显大于 intervalMs。 |
| gpuEnabled | true | 是否采集 GPU。 |
| disksEnabled | true | 是否采集物理磁盘与固定分区容量。 |

无效配置会在注册路由前拒绝加载。Host 配置重载会关闭旧流与旧采集器，客户端下一次连接时读取新配置。

## 指标与资源开销

Windows x64 Worker 保持一个 PDH 查询并复用缓冲区，通过 Koffi 直接调用系统 DLL，不启动 PowerShell、nvidia-smi，也不使用当前会话的子进程执行环境。DXGI 设备清单与固定分区容量低频更新。浏览器图表使用静态 SVG，只在收到采样时更新，不持续播放动画。历史有界地保存在内存中，不写入磁盘或会话日志。

CPU 优先使用 Processor Utility，必要时使用并标明 Processor Time。物理内存使用量为总量减可用量。GPU 利用率先合并同一物理引擎上不同进程的活动，再取最忙引擎；不是所有引擎的相加，也不是显存占用率。专用显存容量来自 DXGI；没有对应性能计数器的 GPU 保留未知实时值。软件适配器不展示。

只有原生 PCI 总线／设备／功能地址与物理节点索引确认同一设备时，才合并 GPU 别名。身份未知、PCI 地址不同或物理节点不同的记录即使同名也保留为独立设备。对于确认的别名，采集器按有效指标字段与引擎数量择一整份报告，不对别名的利用率或显存求和；设备名称仅用于显示，不作为去重键。

物理磁盘活动率由空闲时间推导，读写速率单位为字节／秒；容量属于逻辑分区。同一磁盘上的两个分区不会生成重复的物理读写记录。总计行被排除，避免双计。预热和失败的读取不会给趋势添加虚假的零点。

可选计时诊断与 UI 验收分开。报告放在 .local；仅有采集耗时不能衡量 Host 传输、浏览器绘制或与任务管理器的完整性能对等。

## 安全与生命周期

精确的只读 GET 路由 /api/dsh-system-monitor/config 与 /api/dsh-system-monitor/stream 使用 Connection 既有的 owner 鉴权与来源检查。插件不开新端口，也不注册 Agent 工具。响应只包含 Host 与设备的聚合指标，不提供进程 ID、命令行、文件名或凭据。流读取有界，异常响应明确失败；慢客户端不会累积无限队列。

订阅、样式、路由与标签页注册随插件卸载清理。卸载先停止新请求、关闭流，再请求并等待 Worker 退出。原生查询句柄与临时 DXGI 对象由所属采集器释放。某类指标失败不影响其他类；Worker 失败会明确结束流，供客户端重连。失败后的旧快照不会被重新标记为最新值。

## 开发与验证

开发时，本仓库须位于 Harness 源码树的 `local-plugins/plugins/system-monitor`，因为开发依赖与验证助手使用相对路径。在插件目录执行 pnpm install --ignore-scripts 安装依赖，再执行 pnpm run build、pnpm run typecheck、pnpm test 与 pnpm run test:artifacts。产物冒烟加载实际 Host 与浏览器工厂，读取真实 Windows Worker 采样并检查正常退出。非 Windows 的原生冒烟明确跳过；纯算法和生命周期测试保持确定性。

最新插件构建已供现有本地 GUI 使用、且页面已重载后，再执行 pnpm run test:browser。浏览器验收通过 http://127.0.0.1:3080 的真实 profile 侧栏入口进行，不启动或重启服务。脚本沿用既有只读浏览器鉴权助手，在独立浏览器上下文中创建一个空白测试会话与工作区，不发送提示词，并在 finally 中归档该会话、仅移除其工作区注册。脚本不检查用户对话；凭据与 Cookie 仅在内存中使用，不进入报告、截图或日志。

浏览器验收检查四个按钮切换、默认 GPU 详情、各资源专属详情、当前资源的一条历史趋势、暂停／恢复与重新连接，以及现有 GUI 的浅色主题和继承的 DSH 品牌 token。它对每类资源分别在 390、720 与 1440 视口宽度下仅截取完整监控面板，必要时只增加测试视口高度；.local/browser/report.json 记录检查结果、计算后的语义颜色、布局数据和 12 张截图的名称。GPU 仪表是额外的无障碍图像，不是另一条历史趋势。脚本不设置 body 主题属性，也不引入插件主题开关。可将 DSH_MONITOR_EXPECT_GPU_COUNT 设为 1–64 的整数，断言实时 GPU 清单等于当前选中设备一项加其他设备按钮数；独立确认有两块设备的机器设为 2。

DSH_MONITOR_HMR_TEST=1 另行验证关闭／启用清理，并恢复插件启用状态。可选诊断仍可使用：pnpm run perf:collector -- 30 测量生产 Worker，DSH_TASKMGR_PID 指定已经运行的任务管理器进程；DSH_MONITOR_PERF_SECONDS=30 配合 DSH_MONITOR_HOST_PID 与 DSH_TASKMGR_PID 开启进程／GPU 开销测量，DSH_MONITOR_PROFILE=1 记录渲染采样。这些选项不是 UI 接入验收的前提，也不会产生压力负载。

## 已知限制与待办

原生实时采集目前支持 Windows x64。GPU 引擎计数器需要兼容的 WDDM 驱动；权限或驱动问题可能导致部分字段不可用。非 Windows 或非 x64 Host 明确报告不支持，不静默切换到 Shell 采集。

本插件替代的是资源监控页面，不包括任务管理器的进程管理、启动项、服务控制或结束任务。首版不包含温度、风扇、功耗、远端监控、持久历史与告警。不同链接 GPU 节点可能同名，不支持的节点保留未知值。右栏需要已选会话，并非设置页中的全局面板。

采样窗口与引擎选择可能不同，CPU／GPU 数值不保证与任务管理器逐点相同。UI 接入验收不声称与任务管理器性能对等。
